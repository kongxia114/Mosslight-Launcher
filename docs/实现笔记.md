# 实现笔记

这个文件收两种东西，代码里**不写**：

1. **为什么这么改** —— 某块东西为什么是现在这个做法，改之前踩过什么坑、用户的反馈原话。
2. **来龙去脉** —— 某个功能先后换过几种形态、每个形态栽在哪儿。

代码里的注释只描述**现在**的行为：它做什么、约束是什么、⚠️ 踩了会怎样。
"以前是……后来改成……""2026-10-18 用户实测……"这类句子一律往这个文件里放，
别塞进 `.cs` / `.xaml`。

**往里加的方式**：从代码里删掉一段历史说明时，把那段话按**主题**并进下面某一节
（没有合适的就新开一节，标题写"某个东西为什么是这样"）。小节之间不按时间排序。

---

## 提示框（toast）为什么浮在页面上

原来「收藏成功」这类反馈是往页面内容流里插一条横幅（`NoticeBanner`）。问题有两个：
页面被顶下去一块（布局抖动），而且那条横幅会一直赖在那儿不下来。

用户当时的原话：「这是提示框吧，怎么直接丢页里了？」

现在的做法：右下角浮一层（`MainWindow.xaml` 里的 `ToastHost`），动画进出、几秒后自己走，
不参与页面布局。

## 提示框为什么分四种语气

一开始所有提示都是一个样子（主色 + 勾），可"安装完成""这个版本还没装完""下载失败"
在界面上长得一模一样，用户得读完整句才知道是好事还是坏事。

现在按语气换颜色（`ToastKind`）：成功 / 信息 / 警告 / 错误。版式不变，只换图标、描边
和底下那根进度条的颜色 —— 扫一眼颜色就知道大概发生了什么。

## 提示框为什么用 DockPanel 而不是横向 StackPanel

横向 `StackPanel` 量孩子时给的是**无限宽**，长句子就不换行，卡片直接顶出窗口右边被切掉
（一长句"部分调试信息将在刷新或启动器重启后切换显示"当场露馅）。

`DockPanel` 会把图标之外的剩余宽度交给文字，`TextWrapping` 才真的生效。

## 「装到哪儿？」为什么要先问一句

早期下载直接落到"上次启动的那个版本"的目录，用户没有选择权：想给另一个版本装、
想装进自己整理的文件夹都做不到。

现在点下载先弹一次目录选择（版本列表 / 自定义文件夹），选完把目录交给下载流程。

## 版本列表里点目录为什么必须再问一句

列表里有「启动器目录旁边」这种**算出来的、可能还不存在**的项。1.0.0 有用户报过：
界面高亮着官方目录，下载却装到别的地方去了 —— 因为选中那一刻悄悄把配置改成了
"当前游戏目录"，而界面还在高亮原来那行。

现在点完会弹确认，用户点头才落盘。

## 自检里的语言列表为什么只留一份

`ExpectedLanguages` 那五个语言原来散在三个地方写字面量，改一处忘两处。
现在只有一处常量，下面的断言全从它出发。

## `--page settings:<子段>` 那个 switch 为什么要显式写类型

几个分支是互不相干的控件类型（`ComboBox` / `MemoryBar` / `CheckBox` / `Button`），
switch 表达式自己推不出共同类型，不给 `FrameworkElement?` 会报 CS8506。

## 续铺的提前量为什么是 64

一开始是 160，2026-10-18 用户嫌"滑到底加载有点暴躁"（还没到底就开始往上顶），
压到差不多一个折叠标题的高度（64）。现在离底部 64 以内才续铺，差 120 一律不动。

## 总速度为什么按"已下字节合计"算

原来是把每个任务自己的速度加起来。小文件从开始到结束常常不到 0.25 秒，
这种任务整个生命周期里速度都是 0，加起来会把总速度算成 0，进度条看着像卡住。

现在用"所有任务已下字节合计"在滑动窗口里的变化来算总速度。

## `GameInstaller` 为什么只做规划

1.0.0 那边把"读 JSON / 算清单 / 下载 / 解压"揉在一个方法里，后果是：
清单算得对不对没法单独验（要真联网下几个 G 才知道），规则判断、natives 挑拣、
资源索引这些最容易错的细节全埋在下载流程里。

现在这个类只产出"要下哪些文件"（`InstallTask` 列表 + natives 列表），不联网、不写盘；
下文件交给 `DownloadManager`，解压交给 `NativesExtractor`。

## 主面板为什么只剩这几样

2026-10 按用户要求照 PCL2 的主面板做了一次"极致简化"，删掉了三行：
版本名（跟按钮副标题完全重复）、「Java · 内存 · 加载器 · 隔离」、以及「当前档案」。
后两者没有丢，一个收进启动按钮的 ToolTip，一个只留在左侧栏底部那张卡片上。

## 整合包为什么从"下载页的第三段"变成"拖进来就装"

原来下载页里按 `.mrpack` / 整合包列表 / 本地文件分了三段。现在主入口是"把包拖到窗口上"，
下载页那一栏只是其中一个入口 —— 功能没少，只是少了一个必须站在那一页才能用的前提。

## 主题里那两份 QSS 清单为什么后来补齐了

`Controls.xaml` 里有几段是照 1.0.0 的 QSS 逐条翻译的，其中 `parts/30-badges.qss` 当时整块跳过
（那两个页面还没搬过来），`AnimPresetList` / `SpeedOption` 的键在末尾清单里标着「暂缓」。
后来都补上了，清单也销账了。

## `FindResource` 用错 key 是怎么炸的

2026-10-18 收藏夹那一栏崩过一次：`FindResource("ModCardTitle")` —— 这个 key 不存在，
`FindResource` 不抛"找不到"，而是返回一个"未解析的引用"，强转成 `Style` 时才抛
「Unable to cast MS.Internal.NamedObject to System.Windows.Style」。

所以样式 key 必须用真实存在的（`ModsPage` 搜结果卡那一套：`ModCardName` 等）。

## `AppSettings` 里新加的成员为什么标"只增不改"

这个类要能原样读回 1.0.0 留下的 `config.json`。新加成员如果顺手改了已有键的语义或
默认值，用户那边的旧配置就会被"翻译"错，而且错得很安静。

约定：新成员只加，不动已有成员的签名 / 行为；已有键原样保留、原样写回。

## 数据为什么分两处存

以前全都塞在 `%APPDATA%\Mosslight`：换台机器、把启动器拷到 U 盘，设置就"丢"了，
而且卸载时用户根本找不到那份东西在哪。

现在按"跟程序走还是跟机器走"分：

| 存哪 | 什么 | 为什么 |
|---|---|---|
| `<启动器目录>\Mosslight\` | `config.json`、`favorites.json`、`accounts.json`、`skins/`、各类缓存 | 拷走整个文件夹 = 完整迁移；卸载就是删文件夹 |
| `HKCU\Software\Mosslight\Window` | 窗口宽高、是否最大化 | 跟这台机器这块屏绑着，跟着 U 盘走反而会开出屏幕外 |
| `HKCU\Software\Mosslight\Migration` | 一次性迁移标记 | 同上，机器本地 |
| `HKCU\Software\Mosslight\Update` | **预留**：`Channel` / `LastCheck` / `SkippedVersion` | 自动更新要用，等做的时候直接读写，不再改布局 |

## 注册表值被改坏了怎么办

`RegistryStore` 的读写**永远不抛异常**：键被删、类型不对、没权限 → 一律当"没有"，
调用方走默认值。窗口尺寸还会再夹一次（不小于 `MinWidth/MinHeight`、不大于工作区），
所以手改注册表把宽度写成 99999 也只会得到一个铺满屏幕的窗口，不会崩。

## 旧数据怎么搬过来的

`%APPDATA%\Mosslight` 那份会在**第一次**启动时复制到新位置（`LegacyDataMigration`）：

- 目标已经有 `config.json` → 不动（用户在新版本里跑过了）；
- 旧目录里没东西 → 不动（全新安装）；
- 其它情况 → 复制 `config.json` / `favorites.json` / `accounts.json` / `skins/`，
  **旧文件保留**（搬错了还能捡回来），并在注册表留一个 `Migration\FromAppData` 时间戳。

## 程序目录写不了怎么办（装在 Program Files）

`<启动器目录>\Mosslight` 只是**首选**。判定用的是"真写一下"（建目录 + 写探针文件再删），
不是 `Directory.Exists` —— `Program Files` 下目录存在，但普通用户根本写不进去。

写不进去就整体退到 `%APPDATA%\Mosslight`：`Load` 一开始就定好 `FilePath`，
`Save()` 万一还是失败会**自动再退一次**并把 `FilePath` 换过去，设置页底部那行会写成
「配置位置：…（程序目录写不了，已改存在这里）」，用户照着这行找得到文件。

窗口大小 / 语言这类会话级设置在注册表，跟配置放哪无关 —— 所以回退只影响
`config.json` / `favorites.json` / `accounts.json` / `skins` 这几样。

## 自动更新为什么"只提示、不悄悄替换"

启动时后台查一次 GitHub，有新版就冒一条提示；真正下载替换要用户在设置里点「检查更新」。
自动替换 exe 这种动作不该在用户没点过任何东西时发生 —— 万一新的包有问题，
用户至少知道自己点了什么。

三道闸都在 `UpdateManager` 里：`MOSSLIGHT_DISABLE_UPDATE` 环境变量（`1` / `true`）关掉整个功能、
跑在临时目录 / 盘符根目录时拒绝更新、下载完必须 SHA256 跟 Release 里记的 `digest` 对上
（对不上就删包，宁可这次不更）。

## 为什么要把替换甩给一个 PowerShell 脚本

程序跑着的时候没法覆盖自己的 exe（文件锁）。脚本的活是：等主进程退出 → `Expand-Archive`
把 zip 解到启动器目录 → 删包 → 重新启动 exe → 最后删掉自己。脚本内容是 `Updates\Apply-Update.ps1`，
作为内嵌资源编进 `Mosslight.Core`，运行时解出来写到 `Temp\Update\apply-update.ps1` 再执行
（脚本只此一份，C# 里不抄第二段字符串）。

## 游戏配置为什么只认 config.ini

游戏的路径配置不写 `%APPDATA%`，只认游戏目录里的 `config.ini`：文件不在就按默认内容建一份，
建不了就弹窗退出。这样"配置跟着游戏目录走"这件事是能看见的 —— 换目录、拷走、删掉都清楚。

## 更新检查为什么挂在 MainWindow.Loaded 上

启动那一刻要做的事已经够多了（读配置、算目录、贴界面）。再在那儿同步请求 GitHub，
网络一慢就是"点了图标半天不出窗口"。所以拆成两步：`OnStartup` 只把窗口弄出来，
`MainWindow.Loaded` 之后才 `Task.Run` 去联网。

约定：**网络 / 文件在后台线程，弹窗一律 `Dispatcher.Invoke` 回 UI 线程**；
查不到更新（断网、被墙、10 秒超时）只写一行日志，绝不弹窗 —— 更新失败不该比开不了游戏更吵。

## LastRunVersion 和"更新成功"提示

注册表里记 `Update\LastRunVersion`（上次跑起来的版本）。比当前程序集版本低 = 刚替换完，
这时才弹"更新成功"并展示这一版的 Release 正文；用户点「确定」之后才把记录改成当前版本 ——
没点就不改，下次启动还会再提示一次。第一次装（没有记录）直接记下当前版本，不弹。

## 「更新成功」为什么用 pending_update.json，而不是只比版本号

原来的做法是启动时拿程序集版本跟注册表里的 `LastRunVersion` 比，比出来大就当"刚更新完"。
这套推断在真实链路上会漏：替换脚本跑完、新 exe 起来时，`LastRunVersion` 可能是任何值
（注册表被清过、用户手动覆盖过、旧进程压根没来得及写），于是**更新完了却不弹窗**。

现在改成"事实优先"：下载校验通过、**拉起替换脚本之前**先把「版本号 + 更新日志正文」
写进 `Temp\pending_update.json`；新进程启动第一件事就是看这个文件，读到就弹，
用户点掉之后立刻删掉。版本比对只作为兜底（用户手动覆盖 exe 的情形）。

顺带修掉一个隐蔽 bug：`UpdateWindow` 的 `Closing` 事件**从来没被订阅过** ——
`OnClosing` 写好了但没人调，所以"强制更新关窗退出"和"关窗也要删 pending"两条都是死的。

## "更新包不见了"的真正原因：清缓存排在下载后面

v2.11.3 / v2.11.4 上点了「立即更新」会报「更新包不见了（可能被杀软删了）」。
看着像杀软，其实是**顺序错**：安装流程先下载（zip 落在 `Temp\Update\`），
随后调 `TryClearUpdateCache()` —— 那个方法删的正是 `Temp\Update\` 整个目录，
于是刚下好的包被自己清掉了。

现在清理**只发生在下载之前**（启动时一次、点更新时一次），下载完的包不会再被清。
顺带加了三重确认，下次真遇上杀软也能一眼看出是谁干的：

1. 文件流关闭后立刻 `File.Exists` + `Length > 0`，并记日志（绝对路径 + 字节数）；
2. `await Task.Delay(1000)` 再查一次 —— "刚才还在、1 秒后没了"就是实时防护；
3. 文件在才继续算 SHA256；缺包的报错会写出**它应该在哪**，让用户能去看一眼。
