# 发版流程

## 两个工作流

| 文件 | 什么时候跑 | 干什么 |
|---|---|---|
| `.github/workflows/ci.yml` | push / PR / 手动 | 构建 + 自检 + 界面冒烟 + 试发布**一个**包 + 发行说明自检。**不发 Release** |
| `.github/workflows/release.yml` | 推 `2.x.y` tag / 手动 | 上面那套 + 打**一个** zip + 建 Release |

## 版本号

`主.次.修`（`2.0.0` / `2.0.1` / `2.1.0`），**不带 `v` 前缀**；预发布加 `-alpha` / `-beta` / `-rc`。
唯一来源是仓库根 `Directory.Build.props` 的 `<Version>`；发版时 `dotnet publish` 用
`-p:Version=<tag>` + `-p:FileVersion=<纯数字前四段>` 覆盖，**源码一个字不用改**。

## 发一个版本

```powershell
# 1) 先把这一版的改动写进 CHANGELOG.md 的「## 未发布」
# 2) 打 tag 推上去
git tag 2.0.0
git push origin 2.0.0
```

想重发、或从分支直接发而不打 tag：**Actions → Release → Run workflow**，填版本号。两种触发走同一套步骤。

⚠️ **不写 CHANGELOG 的话发行说明只有一句「没有在 CHANGELOG.md 里找到对应小节的说明」，而且流程照样绿。**
`tools/check_release_body.py` 现在把这件事盯住了（CI 里也跑）。

## 产物：只有一个包

`Mosslight-2.0-<tag>-win64.zip`，里面**只有一个** `Mosslight.exe`。

| 发布参数 | 实测大小 | 运行前提 |
|---|---|---|
| `--self-contained false` + `PublishSingleFile` | exe 2.0 MB / zip **1.4 MB** | 需要 .NET 10 桌面运行时（x64） |

**为什么不发 55 MB 的自带运行时版**：更新一次只下 1.4 MB，几秒钟的事；代价是机器要先装一次运行时。

硬检查：顶层恰好 1 项 `Mosslight.exe`、没有 `Assets\`、没有散装 dll/pdb；
大小门槛 **下限 1 MB + 上限 10 MB**（上限拦「`--self-contained` 被写成 true」）。

## 五个容易踩的点

1. **语言数据是内嵌资源**（`<EmbeddedResource>`，不是 WPF `<Resource>`）。发布产物顶层只能有一个 exe，
   出现 `Assets\` 就算回归。用户仍可在 exe 旁边放 `Assets\lang\zh_CN.json` 覆盖某几条（可选）。
2. **版本号只有一处**：`Directory.Build.props`。界面读程序集属性，所以界面和 exe 属性不可能对不上。
   预发布后缀只能给 `Version`、不能给 `FileVersion`。
3. **`shell: pwsh` 不能省**：PowerShell 5.1 的 `>>` 写 GITHUB_OUTPUT 是 UTF-16，GitHub 按 UTF-8 读会**静默**解析不出 output。
4. **发行说明 = 仓库兜底 + 现场覆盖**：`body_path` 永远指向 `RELEASE_BODY.md`（读不到会直接报错），
   正常发版时「组装发行说明」会把它覆盖成真实 zip 名 / 实测大小 / compare 链接 / CHANGELOG 小节。
   更新内容往 `CHANGELOG.md` 的 `## 未发布` 追加。
5. **`EnableCompressionInSingleFile` 不能加**：框架依赖发布加它是 `error NETSDK1176`。

## 推之前先在本机跑一遍

```powershell
python tools\local_run_workflow.py .github\workflows\ci.yml
python tools\local_run_workflow.py .github\workflows\release.yml --tag v2.0.0-test
```

它把 workflow 在**仓库的临时副本**里真跑一遍（只跑 `run:`，`uses:` 跳过），并模拟
`GITHUB_OUTPUT` / `GITHUB_ENV` / `RUNNER_TEMP`。当初就是靠它抓出一个真 bug：
PowerShell 里逗号优先级比 `+` 高，发行说明整段塌成一行，而且不报错。

⚠️ 本机只有 PowerShell 5.1 时脚本会退回复用它：语法错能抓，但 `Set-Content -Encoding UTF8`
在 5.1 带 BOM、7 不带——涉及编码的地方以 CI 为准。

## 注入凭据（LittleSkin 等）

仓库里的 `Mosslight.Core\Configuration\BuildSecrets.cs` 永远是空占位；发版时由
`tools\make-build-secrets.ps1` 用 GitHub Secrets 生成到工作区（不进 git）：

```yaml
      - name: 注入编译期凭据
        shell: pwsh
        env:
          LS_ID: ${{ secrets.LITTLESKIN_CLIENT_ID }}
          LS_SECRET: ${{ secrets.LITTLESKIN_CLIENT_SECRET }}
          MS_ID: ${{ secrets.MICROSOFT_CLIENT_ID }}   # 预留：没建 secret 时为空，自动跳过
        run: |
          $entries = @(
            "littleskin.client_id=$env:LS_ID",
            "littleskin.client_secret=$env:LS_SECRET",
            "microsoft.client_id=$env:MS_ID"
          ) | Where-Object { $_ -match '=.+' }
          & ./tools/make-build-secrets.ps1 -Entries $entries
```

⚠️ GitHub **不允许** secret 为空值；不需要的键就**别建**，代码里 `BuildSecrets.Has(...)` 会如实返回 false。

## 其它注意事项

- **Actions 页面下的是 artifact，Releases 页面下的是资产**，结构一致（一层 zip、一个 exe）。
  `actions/upload-artifact` 自己会打 zip，所以上传的是 `publish-fx/Mosslight.exe` 这个文件。
- 截图冒烟清单只有**一处**：两个 workflow 顶部的 `env.SMOKE_PAGES`，改完记得同步（`check_workflows.py` 会比对）。
