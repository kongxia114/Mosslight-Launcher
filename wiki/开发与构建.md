# 开发与构建

## 工程结构

```
Mosslight.Core\            类库，**没有 <UseWPF>**
  Theme\                   调色板 + 颜色运算（逐字移植 core/theme.py）
  Settings\                config.json 的读写与类型纠正
  Localization\            i18n：Localizer（磁盘覆盖优先 → 内嵌回落）
    lang\*.json            5 种语言的数据，**<EmbeddedResource> 编进程序集**
  Animation\               入场动效的预设表 + 轨迹引擎（纯函数，不依赖 WPF）
  Appearance\              背景铺法那些常量
  Logging\                 日志：级别 / 续行 / 噪音判定、log4j XML 还原、进程级日志总线
  Configuration\           BuildSecrets（CI 注入的凭据 + 环境变量兜底）
  Services\                数据模型 + 服务接口 + **真实现**（Real*Service.cs）
    Auth\                  LittleSkin OAuth / Yggdrasil 密码 / authlib-injector / 皮肤头像
    Engine\                启动引擎（对应 1.0.0 的 core/*.py）：LaunchRules / LaunchPlanBuilder /
                           VersionScanner / JavaScanner / DownloadManager / LoaderInstaller / ModpackInstaller …
Mosslight.App\             WPF 界面（Themes / Infrastructure / Views）
Mosslight.Core.SelfCheck\  控制台自检（相当于测试工程）
tools\                     生成器与检查脚本（golden、图标、workflow、发行说明…）
docs\                      设计笔记与风格对照（1.0.0 → 2.0 的映射）
tests\                     golden fixture（theme / launch / slide_anim）
```

## 构建与自检

```powershell
dotnet build "Mosslight-Launcher 2.0.slnx" -m:1 -warnaserror
.\Mosslight.App\bin\Debug\net10.0-windows\win-x64\Mosslight.exe

$exe = '.\Mosslight.Core.SelfCheck\bin\Release\net10.0-windows\Mosslight.Core.SelfCheck.exe'
& $exe tests\theme_golden.json              # 离线
& $exe tests\theme_golden.json --net        # + 联网冒烟（真拉清单、真下一个文件校验 sha1）
& $exe tests\theme_golden.json --net-forge  # + 真下 8.4 MB 安装器并跑一次 Forge 安装器
```

其他门禁脚本：

```powershell
python tools\check_lang_keys.py       # 源码用到的文案键是否 5 种语言齐全
python tools\check_workflows.py       # 两个 workflow 的 PowerShell 语法 + SMOKE_PAGES 一致
python tools\check_release_body.py    # 发行说明组装（三种情形真跑一遍）
python tools\check_version_norm.py    # 版本号规范化
```

## 金标准是怎么来的

启动命令拼装是这个项目最容易「看着对、其实错」的地方（rules 的最后一条生效、`${version_type}` 取值、
老版本的 `-Djava.library.path`、log4j 路径替换……每条都是编译能过、跑起来不报错、但游戏就是起不来）。

所以 `tests/launch_golden.json` **不是手写的**，是拿 1.0.0 的 Python 版当权威跑出来的：

```powershell
python tools\gen_launch_golden.py
```

它会在 `tests/fixtures/mc` 造一个假 `.minecraft`（刻意埋 OptiFine 补丁 jar、只有 natives 的库、
坏掉的 version json、版本隔离目录…），把同一批文件喂给 Python 版，结果落成金标准；
C# 自检再读同一批文件逐项比——**命令行的每一项都比**。

入场动画同理（`tests/slide_anim_golden.json`）：用 `QAbstractAnimation.setCurrentTime()` 把真动画逐点定位，
读 `SlideInRow._slide_offset` 和孩子坐标，C# 按同一组时刻算一遍逐点比。

⚠️ 改 `LaunchPlanBuilder` / `VersionScanner` / `SlideInTrajectory` / `AnimationCurves` 之前，
先跑对应生成脚本再跑自检。

## 约定（编译期能兜住的）

1. **`Mosslight.Core` 不引 WPF** —— 用 `<UseWPF>` 缺省让编译器兜住。
2. **颜色只在主题里** —— XAML 不许出现 `#rrggbb`，用 `{DynamicResource BgCardBrush}`（必须 Dynamic，Static 换主题不更新）。
3. **文案都过 i18n** —— `{loc:Tr 启动游戏}` / `Localizer.Tr("…")`，key 就是中文源文案，漏翻退回中文。
4. **主题色是生成的** —— 别手改 `Theme.Dark.xaml`，改 `core/theme.py` 再跑 `gen_theme_xaml.py`。
5. **`Themes\NavIcons.xaml` 是生成物** —— 改 `tools\gen_nav_icons.py` 再跑，图形数据来自 Lucide（ISC）。
6. **注释写「为什么」** —— 尤其是那种"看着可以简化、简化了就错"的地方。

## 离屏截图（自动化验证用）

```powershell
Mosslight.exe --page home --screenshot D:\shots\launch.png
Mosslight.exe --page launch:running --screenshot D:\shots\stop.png   # 运行中的红色结束按钮
Mosslight.exe --page settings:about --screenshot D:\shots\about.png
```

分段页面用 `页面:子段`：`ShowPage` 会在第一个 `:` 处切开，完整 key 留在 `App.ScreenshotPageKey` 里给页面自己判断。

⚠️ 加页面时记得把新 key 加进 `env.SMOKE_PAGES`（`ci.yml` / `release.yml` **各一份**，`check_workflows.py` 会比对）。

## 环境上的坑（Windows）

- **一个 NuGet 包都不能引**（开发机 `api.nuget.org` 不通）——所以自检是控制台程序，JSON 用 `System.Text.Json`。
- `dotnet run` 在这台机器上会因隐式还原崩溃失败；用 `build` + 直接跑 exe，或加 `-m:1` / `--no-restore`。
- 改完源码请用 `-t:Rebuild`：增量判定偶尔误判成"已是最新"，跑的还是旧二进制。
- `dotnet` 默认写 `C:\Users\<用户>\.dotnet`，被沙箱挡住时用 `DOTNET_CLI_HOME` / `NUGET_PACKAGES` 绕。
